# Core

> The plugin entry, the composition root and module host, and the shared plumbing every module builds on: module
> model, service contracts, settings, network helpers, scene lifecycle, game access, UI bases and pure math.

Start with [Plugin.cs](Plugin.cs) (BepInEx entry) and [BoscaliMod.cs](BoscaliMod.cs) (roster in `Compose`, install,
patch, hot-swap, dispose). Architecture: [docs/architecture/ARCHITECTURE.md](../docs/architecture/ARCHITECTURE.md).

## Core or a module?

- **Core**: things two or more modules share without one owning the other: contracts and their data types, the
  module/service/settings/lifecycle model, game seams more than one module patches or reads, engine-free math and
  parsers, UI base classes. Core must not name `BoscaliSummer.Modules.*` (only `BoscaliMod.cs` and
  `Config/ModConfiguration.cs` are allowed; archmap rule R2).
- **A module**: any feature behaviour, its settings, patches, messages, consoles and assets, even if other modules read
  its data (expose that through a `Contracts/` interface instead of moving the code here).
- Many Core files are compiled by path in nomodkit tests (see "Pinned by nomodkit" below): never move or rename them.
