# AvionicsUi

> NOAvionics, the cockpit UI kit every mod console is built with: widgets, style sheets, themes, embedded fonts and
> shaders, and the cross-plugin arbitration of MFD bezel slots and map clicks.

## Why the namespace is `NOAvionics`

The kit was vendored from the shared avionics protocol used by Wing Command and Boscali Summer when they were separate
plugins; each plugin compiled its own copy, and the copies coordinate in-process without a shared DLL
([BezelRegistry](Pure/BezelRegistry.cs) through `AppDomain` data, [MapPicker](Pure/MapPicker.cs)). Wing Command is now
merged in as `modules/Wing`, so this is the only copy, but the namespace, the `NOAvionics.*` resource names and the
`BepInEx/config/NOAvionics/` override folder are kept for compatibility. archmap accepts `NOAvionics` and
`BoscaliSummer.AvionicsUi` as this owner's namespaces.

## Styles

- `avionics.fui.avss` is the base sheet (colour roles only); `avionics.<theme>.avss` are palette sheets
  (`portal`, `steel`, `ace`, `phosphor`, `fieldops`, `amber`, `glass`, `nightops`). Each is embedded with
  `LogicalName` `NOAvionics.avionics.<name>.avss` (see `BoscaliSummer.csproj`) and can be overridden by a file of the
  same name in `BepInEx/config/NOAvionics/`.
- [Plugin.Awake](../Core/Plugin.cs) makes the one `AvStyleHost.Configure(...)` + `AvBundle.Load(...)` call; Command's
  `AvionicsSettingsBridge` applies the theme setting on top.
- Widgets take colours by role name through `AvStyleHost` (e.g. `AvStyleHost.FuiColor("friendly", AvTheme.Friendly)`),
  never literal colours; a missing sheet or bundle falls back to vanilla fonts and built-in colours.

## Rules

- Nothing here references `BoscaliSummer.*`; modules depend on the kit, never the reverse.
- The `.avss` files and `Pure/*.cs` are compiled or embedded by path in nomodkit tests: never move or rename them.
