# Design docs

Verified current structure and the *why* behind decisions that are hard to read back from
the source. Where a doc and the code disagree, the code wins.

- [ARCHITECTURE.md](ARCHITECTURE.md) — one DLL, eight feature modules, how they compose and tear down.
- [MODULE_BOUNDARIES.md](MODULE_BOUNDARIES.md) — the one-module-at-a-time editing map.
- [DESIGN_NOTES.md](DESIGN_NOTES.md) — decisions that cost an argument, kept so they aren't relitigated.
- [ROADMAP.md](ROADMAP.md) — gated future scope. Not a promise, and not a README claim.
- [MODULE_STATUS.md](MODULE_STATUS.md) — per-module inventory of what works vs. is unverified.

Player-facing docs are in the root [README.md](../README.md).
