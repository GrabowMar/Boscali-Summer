BOSCALI CODE ATLAS

Generate or refresh from the repository root:
  pwsh -File tools/CodeAtlas/Build-CodeAtlas.ps1

Open reports/code-atlas/index.html in any modern browser. The report works
offline: its data and pinned Cytoscape.js / D3 libraries are local files.
Copy the whole reports/code-atlas folder to move or share the snapshot.
There is no backend, source upload, npm install or mod deployment.

Views
  Dependency graph: component relationships; select a component for details,
  change Scope to inspect its source-file graph, and use Fit view to recenter.
  Matrix: a row USES a column. Select a populated cell for coupling evidence.
  Size treemap: rectangle area represents nonblank source lines; scope into
  a component to see its files. The source list provides keyboard selection.

The minimum-coupling control filters displayed graph/matrix edges. The
inspector reports complete component relationships from the snapshot.

Measurement
  Loads the evaluated Release BoscaliSummer.csproj with MSBuildWorkspace.
  Counts nonblank physical C# lines, including comments, and unique declared
  named types. File membership follows project Compile items and exclusions.
  An arrow A -> B means A references a type declared in B, including the
  containing type of a referenced method/property/field. Weight is the number
  of unique (source file, referenced internal named type) pairs. Repeated
  mentions in one source file count once. Partial types are attributed to
  their first declaration file in ordinal path order.

This is a static type dependency map, not a runtime call graph, execution
profile, test coverage report or architecture quality score. Reflection,
Harmony discovery, Unity callbacks and serialized/data-driven calls can
create runtime relationships absent from this map. Compilation diagnostics,
unbound identifiers and active preprocessor symbols are recorded in the
measurement notes. A successful extraction does not establish a passing mod
build. The snapshot includes local tracked edits present when it was read.

Checks
  dotnet run --project tools/CodeAtlas -c Release -- --self-test
  node tools/CodeAtlas/Verify-CodeAtlas.cjs

Requirements: .NET 8 SDK, PowerShell, and the same Roslyn/MSBuild packages
already used by tools/DeadScan. A fresh machine needs a one-time NuGet restore
from nuget.org (the project root deliberately disables package sources):
  dotnet restore tools/CodeAtlas/CodeAtlas.csproj --source https://api.nuget.org/v3/index.json

Outputs live under ignored reports/; reusable source lives in tools/CodeAtlas.
